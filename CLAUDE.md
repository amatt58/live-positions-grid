# Live Positions Grid

A personal project: a portfolio positions grid that loads positions over REST and updates them with simulated live prices.

All data is simulated. Never describe this as production software or real trading data.

## Conventions

- Import from `src` with the `@/` alias, e.g. `@/pricing/pnl`.
- Named exports only; no default exports (except where a tool requires one, such as config files).
- No `enum` (`erasableSyntaxOnly` is on). Use string union types.
- `import type` for type-only imports.
- No non-null assertions (`!`). Handle the missing case explicitly.
- No `any`. Use `unknown` and narrow it.
- Tests sit next to the code they test as `*.test.ts`. Import `describe`, `it` and `expect` from `vitest` explicitly.
- Commit messages use conventional prefixes: `feat:`, `fix:`, `chore:`, `test:`, `docs:`, `style:`, `refactor:`.

## Architecture rules

- Calculations are pure functions in `src/pricing/` (market value, P&L, P&L %) and must have Vitest tests, including shorts, zero quantity and missing prices.
- React Query is only for REST data (positions, instruments).
- Live prices never go through React Query. They arrive over a WebSocket and go into a price store, updated in batches.
- UI state (filters, search, paused) lives in a Zustand store.
- Live ticks update the grid imperatively through the Handsontable instance. Don't re-render React on every tick.
- Look up grid rows by symbol, never by on-screen row index.
- Price feeds implement a single `PriceFeed` interface; the UI doesn't know which feed is running.

## Decisions already made

- P&L % = unrealised P&L ÷ (average cost × |quantity|); `null` for zero quantity or zero cost.
- Pause: the feed keeps running; batches stop being applied; resume applies the latest prices.
- Sort order stays fixed during live updates until the user sorts again.
- Filtering is a pure function over the store's values, not Handsontable's Filters plugin.
- Batch interval: 200ms default, configurable.
- The simulated WebSocket uses MSW's WebSocket mocking, so app code uses the browser's real `WebSocket` API.
